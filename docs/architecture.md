# 말해봄 Mk.2 — 아키텍처와 신뢰 경계

## 팀 전체 서비스 흐름

```text
React Web UI
  │ 면접 질문·공고·답변 녹음(WAV)
  ▼
FastAPI ── Whisper STT + VAD ── 전사 결과 확인/수정
  │
  ├─ 공고/질문/답변 근거와 문장 위치
  ├─ FastMCP: 내부 컨텍스트 조회
  ▼
Prompt + Domain Skill → OpenRouter LLM
  ▼
Pydantic / 서버 validator
  │ 구조화 필드·인용·근거 누락·중복 확인
  ▼
Supabase: 사용자별 저장 / 피드백 / 재답변 비교
```

위 구성은 **3인 팀의 전체 아키텍처**이며 이 전체를 개인 단독 작업으로 주장하지 않습니다. 2차 프로젝트는 RAG 검색 기반 구현이 아닙니다.

## 설계의 핵심

1. **근거에 기반한 코칭:** 답변에 나타난 사실과 공고 기준을 분리해 인용·문장 ID에 연결하고, 관찰되지 않은 경험을 임의로 생성하지 않도록 합니다.
2. **모델 출력과 신뢰 경계:** LLM이 자연어 코칭을 생성하되, 저장·권한·상태 변경 및 구조화 응답 검사는 서버에서 책임집니다.
3. **발화 확인 절차:** STT 결과를 사용자가 확인·수정하는 단계와 실제 코칭에 사용된 답변 revision을 구분합니다.
4. **검증 가능한 에이전트:** FastMCP 호출, 인증·DB 저장, 최신 입력의 유효성을 별도 테스트로 확인합니다.

## 개인 집중 영역

- LLM 모델 평가 및 구조화 출력 계약의 실험적 검증
- Whisper Medium QLoRA와 기존 도메인 성능 유지율 확인
- FastMCP·인증·저장 경로의 결함 검출
- PR 정책 검사·CI 등 개발 품질 게이트의 개선

평가 수치 및 완료·미완료 경계는 [evaluation.md](evaluation.md)를, 역할 귀속은 [contributions.md](contributions.md)를 참고하세요.
